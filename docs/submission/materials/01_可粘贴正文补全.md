## 4. 动手实现

### 4.1 做多大、先做什么

方案有两条线，对应两个真实卡住我的环节：Search 上的素材失控，Edit 上的版本失控。我按「先能跑通、再加深约束」落地，而不是先画一张完整体系统架构再实现。

最小可运行范围如下。

模块一（素材库）：画布上选中一张图 → 右键加入命名库 → 视觉模型写出结构字段和检索文本 → 面板里按关键词找到它 → 一键贴回画布。形状搜索、向量库、质量打分不做。

模块二（多轮编辑）：从画布选中图打开会话 → 解析实体树 → 锁定不想动的部位 → 自然语言改一轮 → 自动验收 → 结果成为修改树上的一个节点，可回退、可分支。像素级生产审核、多人锁图不做。

画布上的生图、拆解、局部重绘、文字编辑是已有底座，用来制造「会被弄丢的素材」和「会被改坏的角色」；本次作业的核心验证单元是上面两个模块。

### 4.2 模块一：标注入库怎么跑通

入库必须把像素带出画布。tldraw 图层只有本地资源 ID，没有后端资产号，所以导出 PNG 后再交给 Artifact 存储。

视觉标注复用场景视觉客户端，默认 `qwen3-vl-plus`。模型被要求只输出 JSON：标题、物体、标签、描述、风格，以及闭合词表里的类型 / 视角 / 题材 / 背景 / 姿态，外加主色和材质。词表在前后端各有一份中英对照，非法取值会被归一到 `other` 或留空，避免每个模型自己发明一套标签。

检索是把上述字段拼成 `search_blob` 做子串匹配。游戏资产的常见问法（「全身」「奇幻」「女剑士」「长剑」）可以直接打中；不引入 embedding，是为了把「标注是否可检索」和「向量召回好不好」拆开验证。

标注失败仍落盘，状态记为 `caption_failed`，标题保留用户手填。生产里宁可变「未标注条目」，也不丢图。

前端路径：右键菜单「加入素材库」→ 对话框选库或新建 → 可拖动「素材库」面板筛选、改字段、贴回。拆解后前景和背景经常同时被选中，入库按图层 z-index 取最上层，避免把场景图的标签写到角色 PNG 上。

主要代码：`backend/app/assets/`（仓储、caption、API），`frontend/src/library/`，接口前缀 `/api/v1/assets`。

### 4.3 模块二：多轮编辑怎么跑通

这一模块的 API 前缀是 `/api/v1/controlled-edit`，权限 scope 为 `controlled_edit`，嵌在首页可拖动窗口里，与画布共用当前选中图。

一轮编辑的固定顺序是：意图解析 → 编译提示词与参考图 → 生图 → 构图检查 → VLM 验收 → 失败则带原因重试一次 → 增量重解析实体 → 写入版本节点。Preserve 列表由程序根据锁定 / 确认 / 可改三种状态生成，不让语言模型决定「哪些不能动」。指令打到已锁定实体时直接 409，前端提示先解锁。

模型有明确分工。定位用 Qwen-VL（默认 `qwen3-vl-plus`），因为在同一张骑士图上，gpt-4o 给出的脸、剑、盾框明显偏。改图默认通义 `qwen-image-edit-plus`；剑、盾、手套这类小框走万相 `description_edit_with_mask`（白改黑留）。意图解析和验收仍用 OpenAI 视觉模型。生成模型和质检模型分开，避免同一套权重既当作者又当考官。

小物件与大区域走不同执行器：局部 mask 改剑或盾时，脸和风景基本不动，但握持关系偏「贴图」；换背景、改发型、改整身盔甲走整图指令，并用锁定时刻裁出的脸部参考图锚定身份。硬像素贴回默认关闭，因为误把大区域当局部贴回时，画面上会出现矩形残影。

修改树每个节点保存图像、指令、解析意图、实际发出的提示词、参考图、实体快照、验收分数、重试次数和警告。从任意节点继续编辑即分支；回退只移动当前指针。会话在本地写入 `data/cedit/`，重启后端后双分支骑士会话仍在。

主要代码：`backend/app/controlled_edit/`，前端 `frontend/src/studio/` 与首页坞。

### 4.4 本地如何复现

启动：仓库根目录 `.\scripts\dev.ps1`。前端 `http://127.0.0.1:3000`，API 文档 `http://127.0.0.1:8000/docs`。

需要的密钥：`INFD_DASHSCOPE_API_KEY` 或 `INFD_ALIBABA_API_KEY`（定位、标注、通义改图、万相 mask），`INFD_OPENAI_API_KEY`（意图与验收）。无密钥时对应能力在 capabilities 接口中灰显。

素材库演示：选中画布图 → 右键加入素材库 → 打开素材库面板搜索「长剑」或「角色」→ 贴回画布。

多轮编辑演示：选中骑士图 → 打开多轮编辑 → 锁定 `character.face` → 分别从根节点走出武器线和发型线。

## 5. 成果展示

### 5.1 素材库：生成物变成可找回的资产

在画布上选中整图或拆解后的前景，入库后面板给出标题、类型、视角、题材、姿态、主色、材质、物体列表和一段检索用描述。图 3 中的「版本1」被标成角色 / 全身 / 奇幻 / 站立，物体含少女、剑、盾牌，搜索这些词可以重新找到它。拆解得到的透明底前景与风景背景进入不同条目，避免「一张图既是角色又是场景」的混用。

这解决的是 Search 环节的具体动作：不再靠文件名和时间戳点开排查，也不要求作者在出图当时就写完标签。VLM 先填闭合字段，人再改错的那几项。

### 5.2 多轮编辑：同一张骑士图的两条产品线

用同一张红发女骑士做双分支实验，锁定脸部。A 线只改装备：长剑→火焰弯刀，蓝盾→骷髅黑铁盾，银甲→暗金哥特板甲。B 线从根节点另开：及腰金发卷 → 红羽宽檐帽 → 黄昏海边悬崖。六轮均一次生成通过验收，单轮约 70–75 秒。脸部保持分在 0.8–1.0。版本树在会话「Two-branch knight」中保留，后端重启后可继续点选节点对比。

小物件对照另做三轮：剑→水晶木杖、盾→南瓜灯、手套加金线。前两轮改动可见且脸与风景基本不动；手套金线过细，几乎无变化。这决定了路由规则：太小的装饰不走 mask 赌效果。

定位对照：同一张源图上，gpt-4o 的脸/剑/盾框明显偏；`qwen3-vl-plus` / flash / max 三个 Qwen 模型框都落在正确部位。默认采用 plus，约 14 个实体、22 秒左右。

### 5.3 和「只会调 API」的差别

可运行的不只是对话改图。生产里要留下三样东西：结构化资产记录、带验收分数的版本节点、可从中间分叉的历史。提示词约束、参考图锚定、几何构图检查、VLM 质检是叠在同一条管线上的，任何一层单独拿出来都不够用——早期只靠提示词时，镜头会逐轮推近，表情也会漂。

## 6. 思考过程、失败与边界

### 6.1 为什么这两个痛点排在前面

Create 环节的文生图已经有很多现成工具，Adapt 是后期发行问题。我自己用这套画布做概念图时，时间花在两头：生成之后找不到能复用的那一张；改了三轮之后角色不像原来那个人，且无法回到「只换了发型」的中间态。所以 Search 与 Edit 是我能亲手验证的核心，Review 只做了自动验收这一层轻量质检，没有做成人工审核工单。

### 6.2 实现中改过的错误假设

假设一：局部 crop 编辑再贴回，就能保住没改的区域。实际在「换北欧城堡」时，系统把大背景误判成局部目标，骑士右上角留下一块矩形残影。后来生成侧取消 crop-edit-paste，统一整图编辑，硬贴回改为默认关闭。

假设二：用 gpt-4o 一次完成定位和验收。定位框粗，验收又偏松——镜头明显推近时构图仍打 1.0。于是定位换成 Qwen-VL，验收前增加主体框的几何检查，推近和大幅缩放直接判失败。

假设三：拆解后的前景可以按「当前选中」直接入库。前景与背景常处于多选，面板又可能已经打开，结果是入库成功但界面不刷新，看起来像静默失败。后来改为取最上层图像、入库后广播刷新并选中最新条。

假设四：万相 mask 可以覆盖所有局部改动。它对剑、盾这种中等色块有效，对细金线几乎无效，也不能携带锁定参考图。因此 mask 只留给小物件，身份锚定仍走整图 + 脸部 crop。

### 6.3 仍然存在的问题

VLM 验收对渐进式纹理退化不敏感，长链改图后笔触会变脏，需要从较早节点分支，而不是在脏图上继续叠。分组框（整个 character、environment）仍偏大。检索没有形状/相似度通道，相似构图但文字描述不同的资产会漏。会话与素材索引目前是单机文件，不是多人资产库。Git 远程主分支尚未包含本次模块，评审若只打开 GitHub 网页会看到旧版画布。

### 6.4 若继续做，下一步会很小

形状特征只在素材条目里留了空字段，下一步是把拆解得到的前景做一次轮廓描述或轻量 embedding，解决「侧向持剑」这类构图检索。验收侧用主体框做确定性构图检查已经有效，可以再加一项分辨率/噪声指标，专门抓长链退化。这些都不改变本次已经跑通的主路径。
