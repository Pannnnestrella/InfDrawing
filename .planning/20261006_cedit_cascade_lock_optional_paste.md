## 任务：级联锁定 + 硬贴回改为默认关（可选）

**背景**：锁父节点时子项在冲突规则里已被保护，但 UI 不会显示「已锁定」，用户只好手动全锁。全锁后每个子框都硬贴回，叠残影。硬贴回本身是矩形兜底，不适合默认开启。
**影响范围**：
- `backend/app/config.py`：`INFD_CEDIT_LOCK_PASTE`（默认 `false`）
- `backend/app/controlled_edit/entities.py`：级联锁定/解锁；有效锁定判定供贴回用
- `backend/app/controlled_edit/service.py`：状态更新级联；硬贴回按配置开关
- `backend/app/system/capabilities.py`：暴露 `lock_paste` 开关给前端（可选）
- `frontend/src/studio/EntityPanel.tsx`（及必要时 `StudioWorkspace`）：继承锁定展示与交互
- `docs/controlled_edit.md`、相关单测
**前置条件**：区域约束组合已落地；`find_lock_conflicts` 已沿父链保护后代

### Stage 1: 后端级联锁定规则
- **目标**：锁定父节点时，所有后代写入 `locked`（共享父级语义）；解锁父节点时，仅因级联被锁的后代恢复为 `editable`（若子项曾独立锁定并自有锚点，解锁父时保留子项独立锁定，或简化为：解锁父 → 所有后代解锁——见待确认）
- **成功标准**：单测覆盖「锁 character → face/hair/sword 均为 locked」；「目标 character.hair + 仅锁 character」仍 409；硬贴回关闭时不调用像素贴回
- **状态**：Complete

推荐简化规则（待确认默认采用）：
1. 锁父 → 所有后代设为 `locked`；只给**被点击的那个节点**裁锚点参考图（后代不各自裁锚点，避免占满参考图名额）
2. 解锁父 → 所有后代设为 `editable`（清级联）
3. 锁子 → 只锁该子，不影响兄弟/父
4. 解锁子 → 若父仍锁定，拒绝或保持继承锁定（UI 显示锁定且按钮禁用）——父锁时子项不能单独解锁

### Stage 2: 硬贴回默认关、可配置打开
- **目标**：`INFD_CEDIT_LOCK_PASTE=false`（默认）；为 `true` 时才对「显式锁定且有 bbox」的实体做 `lock_composite`；贴回时跳过「仅因父级级联锁定、自身无独立锚点」的后代，只贴有 `anchor_artifact_id` 的锁定框（或仅贴用户直接锁定的节点），避免整身大框 + 多部件叠贴
- **成功标准**：默认路径单测断言生成结果不做 lock paste；打开开关后仍贴回有锚点的锁定实体
- **状态**：Complete

### Stage 3: 前端级联展示
- **目标**：父锁定时子项显示锁定态；父锁期间子项状态按钮禁用（提示「随父锁定」）；锁定计数含继承；能力/设置不必做复杂 UI，用 env 控制硬贴回即可（文档写明）
- **成功标准**：浏览器打开会话，点锁 character，子项全部显示锁定且不可单独解锁；解锁 character 后子项恢复可改
- **状态**：Complete
